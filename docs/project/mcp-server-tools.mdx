# MCP Server Runtime

The repository now includes a deployable MCP server under `mcp-server/`.

## Transport

The Docker-oriented deployment uses Streamable HTTP.

- endpoint: `/mcp`
- health check: `/healthz`
- methods: `POST`, `GET`, `DELETE`

## Authentication

The default HTTP deployment uses `env-session-token`.

- the server environment must define `KAGI_SESSION_TOKEN`
- clients send `Authorization: Bearer <MCP_BEARER_TOKEN>` on the first `initialize`
- the server resolves and stores the MCP session context
- follow-up requests reuse `mcp-session-id`
- the underlying `kagi` subprocess receives the configured session token from server-side env

Optional local or dev mode:

- `KAGI_MCP_AUTH_MODE=direct-session-token`
- first `initialize` request uses `Authorization: Bearer <KAGI_SESSION_TOKEN>`

## Supported Tools

Session-compatible tools:

- `kagi_search`
- `kagi_quick`
- `kagi_summarize`
- `kagi_assistant_prompt`
- `kagi_assistant_thread_list`
- `kagi_assistant_thread_get`
- `kagi_assistant_thread_export`
- `kagi_ask_page`
- `kagi_translate`

Public tools:

- `kagi_news`
- `kagi_smallweb`

## Intentionally Not Exposed In HTTP Mode

These require `KAGI_API_TOKEN`, so they are not registered in the Docker/HTTP runtime:

- `kagi_fastgpt`
- `kagi_enrich_web`
- `kagi_enrich_news`

`kagi_summarize` is also restricted to the subscriber summarizer path in HTTP mode.

## Local Run

```bash
cargo build
cd mcp-server
npm install
npm run build
export KAGI_SESSION_TOKEN='https://kagi.com/search?token=...'
export MCP_BEARER_TOKEN='replace-with-a-long-random-token'
npm start
```

The server listens on:

```text
http://0.0.0.0:3000/mcp
```

## Docker Build And Run

Build from the repo root:

```bash
docker build -f mcp-server/Dockerfile -t kagi-cli-mcp .
```

Run the container:

```bash
docker run --rm -p 3000:3000 \
  -e KAGI_SESSION_TOKEN='https://kagi.com/search?token=...' \
  -e MCP_BEARER_TOKEN='replace-with-a-long-random-token' \
  ghcr.io/changsoonkim/kagi-cli-mcp:latest
```

Then initialize the MCP session with the server access token:

```http
Authorization: Bearer <MCP_BEARER_TOKEN>
```

## Operational Notes

- the MCP server shells out to the local `kagi` binary for every tool call
- the Rust CLI remains the source of truth for auth rules and API behavior
- default tests do not require real credentials
- adapter integration tests run against mocked Kagi endpoints using the real local `kagi` binary
- deployment examples and update notes live in `project/mcp-server-deployment`
